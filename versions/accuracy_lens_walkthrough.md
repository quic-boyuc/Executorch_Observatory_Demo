The Accuracy Lens follows the Observatory protocol to measure accuracy, compare pipeline stages, and surface the result in the HTML report and CI output.
1. `on_session_start` installs backend-specific dataset patches registered through `register_dataset_patches`, so calibration inputs are captured when the user script loads a dataset. This lets the lens reuse the user’s real data without requiring changes to the script.
2. `observe(artifact, context)` respects `config.accuracy.enabled`, including per-region enable or disable overrides, then lazily initializes on the first “Exported Float” record by extracting the float model and building an evaluator with the captured dataset and auto-detected metrics. This keeps accuracy work opt-in for each region and avoids evaluator setup until there is a valid baseline to compare against.
3. `observe(artifact, context)` skips artifacts that are not a Module, GraphModule, or ExportedProgram, and otherwise runs `evaluator.evaluate(artifact)` to produce metrics such as PSNR, MSE, cosine similarity, and top-k accuracy while tracking `_worst_indices`. This records only meaningful model stages and preserves the worst input indices so other lenses can explain where accuracy was lost.
4. `digest(observation, context)` passes the metrics dictionary through unchanged because it is already serializable. This keeps the stored record simple and makes the same values available to later analysis and reporting.
5. `on_session_end` uninstalls all dataset patches and clears cached evaluator state. This prevents one Observatory session from leaking patched dataset behavior or stale accuracy data into the next run.
6. `analyze(records, config)` walks the records and computes per-metric differences between consecutive pipeline stages, such as `psnr_diff` from stage N-1 to stage N, then returns them in `AnalysisResult.per_record_data`. This shows not only each stage’s accuracy, but also where accuracy changed across the export and lowering pipeline.
7. `get_frontend_spec()` returns `_AccuracyFrontend`, whose dashboard renders a TableBlock titled “Accuracy Summary” with `records_measured` and mean primary metrics such as `psnr_mean`, `mse_mean`, and `cosine_sim_mean`, while `json_report()` returns mean, min, max, and worst-record values for CI. This is the table the user sees in the HTML report, while the green-to-red graph color overlay is contributed by the separate per-layer accuracy lens.
