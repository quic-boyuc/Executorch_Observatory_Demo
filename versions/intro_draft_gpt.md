Observatory is a proposed ExecuTorch devtools layer that coordinates model debugging runs and turns collected evidence into one shared report. It sits above existing capture tools and organizes each debugging task as a lens, which is a small plugin that knows how to collect one kind of data and analyze it after the run. It also includes fx_viewer, a browser-based graph viewer for FX graphs, the Python model graphs that ExecuTorch compiler passes transform. Observatory exists because today developers often debug with separate scripts, logs, graph dumps, and tables that are hard to reproduce or share. Each backend team must rebuild the same lifecycle steps, such as when to start capture, what to collect, how to clean up, and how to combine results. Developers also lack a shared graph viewer that can show compiler-stage graphs together with accuracy, profiling, partition, or provenance data. Observatory does not replace Inspector, ETRecord, or ETDump; those tools still own raw runtime capture, while Observatory coordinates and synthesizes their outputs. Users can enter through a zero-code-change CLI, a pass-level decorator, or a Python context manager for manual control. It produces Archive JSON for CI storage and regression checks, and an HTML Report for humans to open in any browser. A proof of concept already exists, and this RFC asks reviewers to approve the stable contracts, schemas, and directory boundaries before production use.
