Today, debugging ExecuTorch backend issues still depends too much on custom scripts that mix instrumentation, capture, analysis, and visualization in ways that are hard to reproduce or share. The core insight in this RFC is to separate capture from analysis: record raw execution and graph artifacts during the run, then analyze and render them offline from a stable archive. Observatory provides the coordination layer for that workflow. It gives engineers a shared lifecycle for sessions, regions, records, archives, and reports, so each backend does not have to reinvent when to start collection, what to store, or how to package results. It also introduces lenses, which are pluggable debugging concerns that know how to collect, analyze, and visualize one kind of evidence. Generic lenses can work across backends, while backend teams can own their specialized lenses independently. For human review, the RFC adds `fx_viewer`, an embeddable graph viewer that can show layered debugging signals inside a self-contained HTML report. Importantly, this does not replace or modify `Inspector`, `ETRecord`, or `ETDump`; those capture primitives and schemas remain unchanged. Observatory sits above them as a client and synthesis layer. What the RFC asks maintainers to approve is the design boundary for four stable contracts: the Lens protocol, the `GraphExtension` API, the Archive JSON schema, and the proposed Report JSON schema.
