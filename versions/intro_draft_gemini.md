Debugging compiler issues in ExecuTorch—PyTorch’s on-device AI runtime—currently forces developers to write fragmented, custom debugging scripts for each hardware backend. These disjointed scripts produce isolated, ad-hoc outputs that are difficult to reproduce or share. To resolve this fragmentation, this Request for Comments (RFC)—a formal proposal seeking design approval—introduces Observatory, a shared workflow coordinator, and fx_viewer, an embeddable graph renderer. Observatory standardizes debugging through a modular extension model of "lenses," which are task-specific plugins handling both data capture and post-run analysis. Importantly, Observatory sits squarely above Inspector and ETRecord—ExecuTorch’s core tools for runtime logging and binary artifact recording—by coordinating their actions without replacing them. Developers can invoke this framework via a zero-code-change command-line interface (CLI), a Python class decorator wrapping compiler passes, or a context manager block. The coordinator synthesizes captured records into a self-contained, interactive HTML report for humans or a structured JSON archive for automated Continuous Integration (CI) systems. While key capabilities are validated in a functional proof-of-concept (POC) implementation, this RFC requests formal approval of the core API contracts and schemas.
